# 按需富集与 Agent 意图触发说明

## 决策

表达—依赖相关性矩阵保持全量预计算；GSEA 按单个表达源基因和基因集集合现场计算，并按完整参数缓存。这样无需为 `19,215` 个表达源遍历全部 Reactome 通路，也不会重复计算已经完成的 `356,073,165` 个相关系数。

## 用户意图

### 聊天中的下一步建议

复用应用现有的回答后建议功能（设置中需开启后续问题建议），不增加模块菜单。建议生成器根据最近对话生成三条自然语言请求，例如“看看全局 ESR1 表达相关的依赖通路”。点击只填入聊天输入框，用户发送后才由 Agent 路由执行。

建议应保留当前基因、表达/依赖测量角色及癌种范围；已有富集结果时优先提示解释 Leading Edge 等后续操作。未知基因或癌种不猜测，不把癌种 GSEA 展示成已支持的直接操作。提示词位于 `src-tauri/src/lib.rs` 的 `FOLLOW_UP_SUGGESTION_PROMPT`，需运行包含本次改动的应用构建才生效；服务器模块文档更新不会自动更新已运行的桌面程序。

以下问题触发 `gene_to_dependency` 能力的 `pathway_enrichment` 操作：

- “ESR1 高表达时更依赖哪些通路？”
- “对 IL6R 表达—依赖结果做 Hallmark 富集。”
- “基于 FOXA1 与全基因依赖的相关性运行 GSEA。”
- “Which dependency pathways are associated with high GPX4 expression?”

触发必须同时包含：

1. 一个作为表达测量的源基因；
2. 通路、富集、GSEA、生物过程或 pathway enrichment 意图；
3. 表达与 CRISPR/Gene Effect 依赖之间的关系。

仅询问“ESR1 高表达时依赖哪些基因”仍然路由到相关性 Top 靶基因查询，不运行 GSEA。仅询问“ESR1 和 FOXA1 是否相关”属于测量含义不明确的问题，不能自动触发本能力。

## 路由与默认参数

### 同义词与上下文（2026-09-08 补充）

`module.intent.json` 的 `semantic_routing` 收录表达量、依赖性、富集及基因集名称的中英文同义词，并提供正反例。模型需同时识别执行请求、表达源基因、表达—CRISPR 依赖关系和通路意图；词语命中本身不执行脚本。

- “继续做富集”只能继承当前已明确的基因、模块、癌种范围和方法；有多个候选基因或上下文不明时先澄清。
- “不要做”“稍后再做”、方法解释、能力询问及引用示例不触发计算。
- “敏感性”必须区分 CRISPR 敲除和药物反应；仅“ESR1 做富集”不足以确定数据模态。
- 用户指定 ORA 时需使用独立 ORA 方法；指定 GO/KEGG 时需准备指定基因集，不替换成默认 Hallmark。
- 低表达请求保留低表达方向；不改变既定正、负 NES 的定义。

这些配置是给模型读取的语义路由指南，尚不是独立自然语言分类器。配置和示例的结构校验不能替代真实模型端到端识别评估。

| 用户信息 | 控制参数 |
|---|---|
| 未指定癌种 | `scope=global`，调用按需 GSEA 脚本 |
| 指定癌种但未明确要求 GSEA | 查询既有 `lineage_gene_enrichment`；该结果是秩和富集，不表述为 GSEA |
| 指定癌种且明确要求 GSEA | 生成新的癌种内完整相关排序后运行 GSEA；不能用仅保留 Top 100 的稀疏边代替完整排序 |
| 未指定基因集 | `collection=hallmark` |
| 指定 Reactome | `collection=reactome` |
| 未指定样本门槛 | `min_pair_fraction=0.8`，26Q1 全局矩阵对应 `pair_n >= 912` |
| 未指定排序方法 | `rank_metric=negative_signed_t` |

Gene Effect 越负表示依赖越强。默认排序分数为：

```text
t = r × sqrt((pair_n - 2) / (1 - r²))
rank_score = -t
```

因此正 NES 表示源基因表达越高，通路成员越倾向于产生更强的 CRISPR 依赖；负 NES 表示源基因表达越高，通路成员越倾向于产生更弱的依赖。

## 可执行入口

服务器全局查询示例：

```bash
Rscript scripts/run_expression_dependency_gsea.R \
  --matrix-root results/expression_dependency \
  --source-gene ESR1 \
  --collection hallmark \
  --cache-root results/expression_dependency_gsea_cache
```

脚本默认从服务器已安装的 `msigdbr` 读取当前 MSigDB Hallmark 或 Reactome。若要严格复现 TM00 的 2023.2 基因集，可传入 `--collection custom --gmt FILE --gene-set-id ID`；提供 GMT 时脚本会强制使用 `custom` 集合，自定义 GMT 必须提供稳定的版本标识，防止错误复用缓存。

## 缓存和结果契约

缓存键包含 DepMap 发布版、源基因、范围、基因集数据库版本、排序指标、`pair_n` 门槛、基因集大小范围、展示数量和随机种子。相同请求读取已有 `result.json`，并在标准输出返回 `cache.hit=true`；参数或数据库版本改变时建立新的缓存目录。

每次新计算输出：

- `enrichment.parquet`：全部合格通路的 NES、P 值、源基因内 BH-FDR、Leading Edge 和方向；
- `ranked_dependency_targets.parquet`：实际进入富集的完整依赖基因排序；
- `top_pathways.pdf`：正负 NES 的主要通路；
- `run_manifest.json`：输入、参数、软件和数据库版本；
- `result.json`：供 Agent 返回的紧凑结果；
- `qc.json`：发布版、基因、样本门槛、方向和多重检验检查。

富集仍是观察性关联结果，不能直接解释为因果调控、药物疗效或合成致死。
