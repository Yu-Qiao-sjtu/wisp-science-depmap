# 06–11 突变脚本数理逻辑审计

## 1. 审计结论

06–11 六个脚本共同覆盖了“突变事件定义 → 癌种内锚点选择 → 固定突变找依赖靶点 → 固定依赖靶点找突变标志物”这条完整链路，但它们不是六份可以等价互换的正式分析脚本。

| 脚本 | 正确定位 | 当前是否可作为正式统计结论 |
|---|---|---|
| `06_mut_anchor_gene_selection_26Q1.R` | 选择每个癌种中样本量足够的突变锚点 | 用于候选菜单；不能证明突变与依赖有关 |
| `07_mutant_dependency_26Q1.R` | 成对验证、正向扫描、反向扫描 | 六个脚本中最接近正式统计核心；需要修正有效样本数、缺失值和癌种混杂 |
| `08_mutData_updata_26Q1.R` | 比较长表、自定义蛋白改变、官方 Damaging、官方 Hotspot | 用于事件定义审计；自定义九类事件不能叫作官方 Damaging |
| `09_batch_from_mut_to_target_26Q1.R` | 固定突变，按癌种汇总全部依赖靶点 | 只作探索；`Score` 没有 P 值、置信区间或 FDR |
| `10_batch_from_mut_to_target_26Q1_add_celltype.R` | 在 09 基础上保留各癌种分数 | 只作探索；癌种列可用于定位信号，不能单独作显著性证据 |
| `11_batch_from_gene_to_mut_26Q1_add_celltype.R` | 固定依赖靶点，反查全部突变基因 | 只作探索；“某癌种特异”判定仅取最大分数，证据不足 |

项目中的统一原则是：**06 负责决定“能不能分析”，07 的 Welch 检验和方向内 BH FDR 负责回答“是否有关联”，08 负责解释“突变事件是什么”，09–11 的旧 Score 只保留为可视化优先级。**

## 2. 统一符号和正式统计量

对细胞系 \(i\)、突变事件 \(e\)、依赖靶基因 \(g\) 和癌种 \(l\)，定义：

- \(M_{ie}=1\)：细胞系 \(i\) 在事件 \(e\) 下为 Mut；
- \(M_{ie}=0\)：发布矩阵明确记录为 0，即该口径下未检出；
- \(M_{ie}=NA\)：状态未知，必须排除，不能归入 WT；
- \(Y_{ig}\)：`CRISPRGeneDependency` 概率，越大表示越可能依赖靶基因 \(g\)；
- \(L_i=l\)：细胞系属于癌种 `OncotreeLineage`。

每一对 \((e,g)\) 都先构造完整观测集合：

\[
C_{eg}=\{i: M_{ie}\in\{0,1\},\;Y_{ig}\text{ 非缺失},\;L_i\text{ 满足当前范围}\}
\]

然后报告实际参加该对比较的样本量：

\[
n_{Mut}=\sum_{i\in C_{eg}} I(M_{ie}=1),\qquad
n_{WT}=\sum_{i\in C_{eg}} I(M_{ie}=0)
\]

Dependency 概率口径下的正式效应量为：

\[
\Delta_{eg}=\bar Y_{Mut}-\bar Y_{WT}
\]

- \(\Delta>0\)：突变组对靶基因更依赖，是候选脆弱性方向；
- \(\Delta<0\)：突变组对靶基因较不依赖；
- \(\Delta=0\)：两组均值没有差异。

若改用 `CRISPRGeneEffect`，数值越负表示依赖越强，因此候选方向改为 \(\Delta<0\)。两种指标不能合并排序。

07 使用 Welch 两独立样本 t 检验。其统计量为：

\[
t=\frac{\bar Y_{Mut}-\bar Y_{WT}}
{\sqrt{s^2_{Mut}/n_{Mut}+s^2_{WT}/n_{WT}}}
\]

自由度采用 Welch–Satterthwaite 近似。它不要求两组方差相等，适合 Mut/WT 样本量不平衡的情况。正式结果还应补充均值、标准误或 95% 置信区间，避免只用 P 值判断。

多重检验族必须与用户问题一致：

- 正向：固定一个突变事件，在全部依赖靶基因中做一次 BH 校正；
- 反向：固定一个依赖靶基因，在全部突变事件中做一次 BH 校正；
- 癌种内结果：每个癌种和查询方向分别记录检验族，不能把泛癌 FDR 当作癌种内 FDR。

## 3. 06：癌种内突变锚点选择

### 3.1 它回答什么

06 不计算依赖关联。它回答：某个癌种中的某个突变事件是否有足够的 Mut 和 WT 细胞系，可以进入后续检验。

脚本先把矩阵转换成二值状态：

```text
Damaging > 0 → Damaging-Mut
Hotspot > 0  → Hotspot-Mut
0            → 对应事件的 WT
```

然后用癌种设计矩阵 \(L\) 和二值突变矩阵 \(M\) 做矩阵乘法：

\[
N_{event,lineage}=M^T L
\]

这等价于逐个基因、逐个癌种统计突变阳性模型数，但速度更快。WT 数量为该癌种总模型数减 Mut 数量。

### 3.2 当前门槛的含义

| 门槛 | 用途 | 解释 |
|---|---|---|
| Mut≥3、WT≥5 | 标准探索菜单 | 保证至少能形成两组；小样本结果仍很不稳定 |
| Mut≥10、WT≥5 | 严格锚点菜单 | 更适合选择后续重点研究的癌种内事件 |
| 泛癌 Mut≥30 | 旧脚本的全局 shortlist | 仅是人工优先级，不是突变定义或统计显著性门槛 |

候选菜单门槛和成对检验门槛承担不同任务，不需要强行设成同一个数字。当前项目保留 3/5 作为浏览入口、10/5 作为严格癌种内推荐；正式成对检验至少使用完整观测后的 Mut≥5、WT≥10，并完整报告实际人数。

### 3.3 已确认的问题

1. 原脚本把 `cellinfor`、Damaging 和 Hotspot 做三者共同交集。这会导致一种事件的数据覆盖限制另一种事件。当前 26Q1 两个矩阵恰好都有 1,968 个相同默认模型，所以没有实际损失；统一模块仍应让每种事件分别与 Model 和 Dependency 取交集。
2. 原脚本用硬编码的 TSG、OG、druggable 和已知合成致死列表。它们适合示例，不能代表完整知识库。当前模块已改用全基因 HGNC、OncoKB 派生角色和 Common Essential 缓存，同时保留未解析基因。
3. `mut_n>=30`、`max_tissue_share>0.8` 和排除 druggable 都是启发式筛选。特别是“可成药”不应成为删除突变锚点的理由。
4. `max_tissue_share` 描述事件的组织集中度，不能证明癌种特异性。癌种特异性需要癌种内效应、癌种间差异及其不确定性。

## 4. 07：正式关联统计核心

### 4.1 三种查询

07 的 `mutStat()` 实现同一张“突变事件 × 依赖靶基因”矩阵的三种读取方式：

| 查询 | 固定项 | 遍历项 | FDR 校正范围 |
|---|---|---|---|
| 成对 | 突变事件和靶基因 | 无 | 单次检验时报告 P；若来自候选筛选，还要说明筛选族 |
| 正向 | 一个突变事件 | 18,531 个依赖靶基因 | 全部靶基因 |
| 反向 | 一个依赖靶基因 | 所有合格突变事件 | 全部突变事件 |

这正好对应用户的两个核心入口：

- “ARID1A 损伤突变后更依赖哪些基因？”是正向；
- “哪些突变让细胞更依赖 PARP1？”是反向。

### 4.2 做对的部分

- 使用 Gene Dependency 概率，并把 `Mut均值-WT均值>0` 解释为突变组更依赖；
- 使用 Welch t 检验，不强制两组方差相等；
- 正向和反向分别做 BH FDR；
- 同时保存差值和显著性，而不是只保存排名。

### 4.3 必须修正的部分

1. **有效人数要按每一个靶基因重新计算。** 原函数先按突变矩阵统计 Mut/WT，再让 `t.test()` 内部忽略 Dependency 缺失值，所以输出人数可能大于实际检验人数。
2. **门槛也要检查完整观测人数。** 应先删除 `M` 或 `Y` 缺失，再判断 Mut≥5、WT≥10。
3. **突变 NA 不得改成 0。** 当前 26Q1 两个官方矩阵实测没有 NA，因此原代码的 `NA→0` 没改变本次数据；这条写法仍应移除，以免未来发布把未知状态误当 WT。
4. **泛癌检验需要处理癌种构成。** 简单泛癌 Welch 检验可能把“某突变集中于某癌种，而该癌种本来就依赖某靶点”误判为突变效应。推荐同时给出癌种内结果，或拟合：

\[
Y_{ig}=\beta_0+\beta_1M_{ie}+\sum_l\gamma_l I(L_i=l)+\epsilon_i
\]

其中 \(\beta_1\) 是控制癌种后的突变关联。它仍是观察性关联，不自动等于因果或已验证合成致死。
5. Volcano 图应把“更依赖”和“较不依赖”分开着色。`abs(Delta)>0.05` 只表示差异较大，不能把两个方向都叫合成致死候选。
6. Top 20 应先限定方向、效应阈值和 FDR，再按效应或 FDR 排序；不能只取 Difference 最大的 20 个。

## 5. 08：突变事件定义审计

08 的价值是说明“有突变记录”“功能丧失”“热点”和“研究者自定义蛋白改变”是不同事件。

| 事件 | 来源 | 正式用途 |
|---|---|---|
| AnySelected | 发布长表中有保留记录 | 完整突变概况和具体位点入口 |
| Damaging | 官方 LikelyLoF 聚合矩阵 | TSG/LoF 假设 |
| Hotspot | 官方热点聚合矩阵 | OG/GoF 或复发热点假设 |
| 自定义九类 | 9 类 `VariantInfo` 白名单 | 方法对照，不作为官方 Damaging |

自定义九类包含 missense、frameshift、stop、splice 和 in-frame indel。因为绝大多数错义突变未必改变功能，把这张矩阵称为“损伤性”会夸大证据；统一命名应是“自定义蛋白改变事件”。BRAF V600E、KRAS G12D 等问题优先使用 Hotspot 或具体 `ProteinChange`，而不是把所有 missense 合并。

原脚本从“至少有一个九类变异”的模型开始 `pivot_wider()`。从方法上说，应先建立完整合格模型集合，再把观测到的事件左连接进去；否则未来若某模型完全没有入选事件，它会从矩阵中消失而不是成为明确 WT。26Q1 实测 1,968 个默认模型都至少有一条九类事件，因此本次没有实际丢失模型。

## 6. 09–11：旧 Score 的数学含义

对癌种 \(l\)，三个脚本定义：

\[
S_l=\bar Y_{Mut,l}
\]

\[
D_l=\bar Y_{Mut,l}-\bar Y_{WT,l}
\]

10 和 11 的癌种分数为：

\[
Q_l=100\times S_l\times D_l
\]

09–11 的总分为：

\[
Q_{all}=100\times mean_l(S_l)\times mean_l(D_l)
\]

这里的总分不是 \(mean_l(Q_l)\)，也不是合并所有细胞系后的效应。各癌种被等权平均，所以 Mut=3 的小癌种与 Mut=30 的癌种权重相同。

`Score` 的局限包括：

- 它把“突变组本身依赖程度”与“Mut/WT 差异”相乘，偏向本来就普遍依赖的基因；
- 没有标准误、置信区间、P 值或 FDR；
- 不同癌种样本量没有进入权重；
- 它不能区分稳定的小效应与噪声造成的大效应；
- 它不是合成致死的统计定义。

因此项目只把 Score 保留为旧图的**探索性可视化优先级**。Agent 不得用 Score 单独宣称“显著”“癌种特异”或“合成致死”。

### 6.1 09 和 10：固定突变找靶点

两者方向正确：固定 `mutGene`，遍历全部 `targetGene`。10 比 09 多保存各癌种的 \(Q_l\)，并通过癌种名称对齐分数列，结构上优于 09。两者都应由 07 式的完整观测 Welch 检验和正向 BH FDR 替代正式排名。

### 6.2 11：固定靶点找突变

11 的方向也正确：固定 CRISPR 依赖靶基因，遍历 Damaging 突变基因。但旧版“Breast-specific/Ovary-specific”只是判断目标癌种的 Score 是否等于该行所有癌种的最大值。它没有要求：

- 该方向为突变组更依赖；
- 该癌种内 FDR 显著；
- 与第二高癌种有足够差距；
- 与其他癌种的效应差异显著。

正式“癌种特异”至少应报告该癌种的 \(\Delta\)、置信区间和 FDR，并增加事件×癌种交互项或做癌种间效应比较。11 还只遍历 Damaging，反向查询 Hotspot 或具体位点时必须切换相应事件源。

## 8. 项目采用的统一执行顺序

1. **解析意图**：识别癌种、突变源、事件定义、依赖靶点和查询方向。
2. **选择事件**：TSG/LoF 优先 Damaging；OG/GoF 优先 Hotspot；具体位点使用 ProteinChange；不明确时先返回各事件人数。
3. **建立独立队列**：每种事件分别与 Model 和指定 Dependency 指标取 ModelID 交集。
4. **保留三态**：`>0=Mut`、明确 `0=WT`、`NA=未知并排除`。
5. **逐对完整观测**：先去掉事件或依赖缺失，再计算实际 Mut/WT 人数并应用检验门槛。
6. **计算效应和不确定性**：报告两组均值、\(\Delta\)、95% CI 和 Welch P 值。
7. **按查询方向校正**：正向与反向分别做 BH FDR。
8. **检查癌种混杂**：同时给癌种内结果或癌种校正模型。
9. **解释候选**：标记 Common Essential、事件机制、癌种构成和小样本风险。
10. **按需富集**：只对用户选定方向和阈值后的候选集做富集，并记录背景基因集。

## 9. 正式结果最小字段

每一行突变—依赖结果至少包含：

```text
release, scope, lineage,
event_type, source_gene, protein_change,
dependency_metric, target_gene,
n_mut, n_wt, n_unknown_event, n_missing_dependency,
mean_mut, mean_wt, delta_mut_minus_wt,
ci_low, ci_high, p_value, fdr, fdr_family,
direction_label, common_essential_target,
analysis_script, parameters, run_id
```

其中 `direction_label` 在 Dependency 概率口径下取 `mutant_more_dependent`、`mutant_less_dependent` 或 `not_resolved`。`Score` 可以作为附加旧字段保存，但不得代替以上统计字段。

## 10. 对 Agent 的约束

- 用户问“某癌种有哪些突变基因可选”时调用 06 的锚点菜单，不把候选人数当关联证据。
- 用户给定突变事件时运行正向查询；给定依赖靶点时运行反向查询；两者都给定时运行成对验证。
- 用户只说“基因突变”时，先展示 Damaging、Hotspot、AnySelected 和可用位点，不擅自合并。
- 只有 `Dependency + Delta>0` 或 `GeneEffect + Delta<0` 才是“突变组更依赖”的方向。
- 只有达到有效样本门槛且通过相应方向 FDR 的候选，才能称为统计支持的关联候选。
- 即便通过 FDR，也只能写“候选依赖关联”或“候选合成致死方向”，不能写成已验证机制或临床结论。
- 旧 Score 只能帮助浏览，不得触发“显著”“癌种特异”或“已发现合成致死”的表述。
